To understand CSRF, and why it is named so, let us consider an example, suppose a website exists, which uses some kind of functionality to change the user's email, a really simple way to do this would be something like the following
```
POST /email/change HTTP/1.1 
Host: vulnerable-website.com 
Content-Type: application/x-www-form-urlencoded 
Content-Length: 30 
Cookie: session=yvthwsztyeQkAPzeQ5gHgTvlyxHfsAfE 

email=wiener@normal-user.com
```
Now as one can see the only authentication the website seems to be using is a simple cookie, this can be exploited using CSRF, consider a attacker who wants to take over a user account by changing their email to one under their control and then resetting the password or something else.

The attacker hosts a website with html which looks like this
```
<html>
	<body>
		<form action="https://vulnerable-website.com/email/change" method="POST">
			<input type="hidden" name="email" value="attacker_ctrl_email@gmail.com">
		</form>
		<script>
			document.forms[0].submit();
		</script>
	</body>	
</html>
```
If the user decides to visit this website then a request will be sent from his browser and the browser will attach the cookie with it and the email will be changed without the user noticing anything, this is the simplest and most common form of CSRF vulnerability, and one can very easily see where the name comes from.

Delivering CSRF attacks is pretty similar to reflected XSS attacks, the malicious code is on a attacker controlled website, if CSRF involves a get request, then the code can be even simpler, on might combine a stored XSS with a CSRF as well.

### Common Defences against CSRF

- __CSRF Tokens__: It is a unique, unpredictable value generated by the server side application which must be included in the request by the user for making sensitive operations, making it harder for a attacker to impersonate a user.
- __SameSite Cookies__:  It is a browser security defence mechanism, which determines when a website's cookies are included in requests originating from other websites.
- __Referrer based Validation__: Some applications use HTTP referer headers to defend against CSRF attacks, to verify that the request originated from the applications domain.
